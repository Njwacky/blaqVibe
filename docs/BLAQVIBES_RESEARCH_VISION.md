## The structural change

**Code is getting cheaper.**  
**Proving, verifying, understanding, maintaining and applying that code is becoming more valuable.**

Stack Overflow 2025: 84% use or plan to use AI tools; 46% distrust accuracy vs 33% who trust it; 66% say AI is “almost right, but not quite”; 45% say debugging AI code takes more time. 75% would still ask a person when they do not trust AI.

DORA 2025: AI is an amplifier of the underlying system, not a magic fix.  
GitHub / OpenAI / Anthropic: humans steer, agents execute.  
Vibe-coding research: generation → evaluation → revision. Strong for prototypes. Weak for maintainability, production, safety. Security risk: volume of AI code faster than humans can review.

**Old workflow:** UNDERSTAND → WRITE → DEBUG → TEST → SHIP  
**AI-native:** UNDERSTAND → SPECIFY → DELEGATE → OBSERVE → TEST → VERIFY → SECURE → SHIP → MAINTAIN → LEARN

## Two wounds (both true)

1. **Visibility:** I built something and nobody saw it. A repo without witnesses is a diary.
2. **Credibility:** I built something (often with AI) and I don’t know if it proves I can actually build.

Visibility without credibility is a costume.  
Credibility without witnesses is a museum.

BlaqVibes attacks both.

## What this product is (combined)

**Not:** a social network for builders. Too weak.  
**Not:** LinkedIn with ZIPs. Job-as-north-star will punish remix, AI honesty, unfinished truth.  
**Not:** “real developers write every line.” That argument already lost.

**Yes:**

GitHub stores code.  
LinkedIn stores claims.  
TikTok stores attention.  
**BlaqVibes stores demonstrated capability in motion — an object other people can open, verify, remix, and keep your name on.**

AI is a tool. Human judgment is the responsibility.  
The enemy is **unverified creation**: generate → publish → disappear.

One sentence:

> BlaqVibes helps people turn (often AI-assisted) creation into credible proof of what they can build, how they think, and what they can do next — with lineage, so the next person can go further without erasing them.

Shorter: **BUILD. VERIFY. PROVE. SHARE. GO FURTHER.**

Homepage energy:

> AI can write the code. Can you prove the build?  
> Don’t tell people what you can do. Leave an object they can open.

## Guardrails from the street-corner thesis

- Opportunity is a **side effect of the object**, not a Jobs tab. Nexters: remixer, user, collaborator, problem-owner who found the *work*. Not an HR meat aisle.
- Stars are status and unlocks, **not salary**. Launch guides are the door to real hosts/stores.
- Remix is the cultural verb. Credit is automatic.
- Trust is evidence, never a fake green badge that claims “this app is secure.”
- First 10 minutes: a public object with a WhatsApp-ready URL. Not a perfect profile.
- Geography is a weapon: WhatsApp, prepaid, Mzansi voice.

Feature knife — ship only if YES to both:

1. Does this make the **object more true** (files, scan, lineage, AI, problem, failure, improvement)?
2. Does this make it more likely **another human does something with the object** (run, remix, review, message about the work)?

North-star metric: **builds that cause something else to happen** (remix, review, improvement, use) — not MAU/likes.

## The Build (central object)

A published project is a **Build**: living record, not a post.

| Layer | Meaning |
|---|---|
| Problem | What were you solving? |
| Intent / spec | What did you ask for? |
| Artifact | Files, README, preview-or-honest-no |
| AI | Tool, notes, what the human did, what AI got wrong |
| Evidence | Scan, tests if present, secrets, deps — precise checks, not one fake “verified” |
| Failures | Bugs, AI misses, fixes |
| Lineage | Parent remix, children, what changed and why |
| Next | Remix, launch, improve |

**Build graph** already starts as `forked_from` + `ProjectEvent`. Deepen it; do not invent a second universe of objects.

## Phased build (do not fake later phases)

### Phase 1 — Proof (NOW)

Build object fields that make a Proof Card: problem, human contribution, AI-got-wrong, remix delta.  
Verification list already on the detail page, made shareable.  
WhatsApp share of the public Build URL.

### Phase 2 — Community (IN CODE)

Reviews as “can I run it / is the README honest.” Remix “what I changed / why” **required** on a remix edit. Today as next action (build / problem / remix / review).

### Phase 3 — Skill (IN CODE)

Skills counted from published evidence only. No giant Builder Score. AI maturity only from work.

### Phase 4 — Opportunity

Problems and challenges as work-shaped quests. Matching via **projects**, not talent profiles. Proof CV generated from work.

### Phase 5 — Trust depth

Ship-readiness as **precise checks** (tests detected, scan completed, 3 vulns found). Maintenance history. Never “BlaqVibes guarantees this is secure.”

## 5 Whys (final)

1. Why AI? Creation got fast and accessible.  
2. Why a new problem? More software than people can understand, verify, secure, maintain.  
3. Why that matters? Generating code is no longer a differentiator. Judgment is.  
4. Why BlaqVibes? A place to demonstrate that judgment on a public object with witnesses and lineage — not a claim on a CV.  
5. Deeper need: **I want what I can do to be visible, credible, and useful — and still mine when someone goes further.**

## Manifesto

AI should make more people capable of creating.  
Using AI should not make honesty optional.  
A generated app is not automatically a good app.  
A finished-looking interface is not proof of engineering.  
A repo, a certificate, a follower count, a prompt — none is the whole story.  
The work, the decisions, the failures, the verification, the remix names — those are.

**What you can actually do should be visible.  
What you actually did should be hard to fake.  
Who you remixed should stay on the object.**
